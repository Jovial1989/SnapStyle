# Looktok VTON — архитектура бэкенда (обновлено 27.07.2026)

Целевая система: мгновенный браузинг на клиенте + фотореалистичная генерация
на бэкенде (15–20 с допустимо). Этот документ — рабочий блюпринт и границы
build-vs-buy, проверенные лицензиями и замерами, а не академический wish-list.

## Вердикт по референсам (проверено 27.07)

| Компонент | Лицензия | Пригодность |
|---|---|---|
| SMPL / SMPL-X | Research free; **коммерция — платная лицензия Meshcapade** | ⛔ фундамент продукта строить нельзя |
| GALA (snuvclab) | Apache-2.0, но «**non-commercial research only**»; вход — 3D-скан, не фото | ⛔ не наш кейс вообще |
| SMPLpix | Пер-субъектное обучение на видео; зависит от SMPL-X + SMPLify-X | ⛔ не VTON; масштабируется как «одна модель на юзера» |
| IDM-VTON | **CC BY-NC** | ⛔ селф-хост закрыт; через fal — забота fal |
| Kolors VTON via fal | Коммерческий доступ через fal.ai | ✅ работает у нас в проде |
| Своя модель на своих данных | Наши веса | ✅ единственный чистый путь к селф-хосту |

Ключевой технический факт: современные диффузионные VTON **не требуют явного
3D-меша**. Kolors/IDM внутри уже используют pose/densepose-кондиционирование и
garment-warping — пункты «SMPL-регрессия + UV-проекция» из спеки заново, хуже
и дороже, реализуют то, что модель делает сама. 3D-твин как вход нейрорендеру
— архитектура SMPLpix-2021, индустрия ушла на прямое кондиционирование.

## Архитектура (staged)

### Stage A — live сегодня ($0 инфраструктуры)
```
клиент (2.5D canvas, engine-3d/viewer/index.html)
  └─ LooktokBridge {type:'generate-vton', garmentId, category}
       └─ Flutter: LooktokApi.generateVton()
            └─ EF generate-vton (JWT + квоты + гейт категорий)
                 ├─ фото профиля (body-photos) + флэт-лей (catalog)
                 ├─ fal-ai/kling/v1-5/kolors-virtual-try-on   ~14 c · $0.07
                 ├─ re-host → bucket `vton` (постоянный URL)
                 └─ insert look_generations + burnFree ПОСЛЕ успеха
```
Замер end-to-end: **16–18 с** (не 5; 5 не даёт никто из диффузионных).

Контракт (совпадает со спекой, задеплоен и проверен):
`POST /functions/v1/generate-vton {garmentId, category}` →
`{ok, url, generationId, entitlement}` · 402 квота · 409 нет фото · 422 категория.

### Stage B — качество входов + данные (без GPU, недели)
- Каноничное фото: cutout/rembg уже есть (removeBackground EF); подавать в
  Kolors чистый full-res вход — качество растёт бесплатно.
- Датасет для своей модели: wardrobe-пары (ground truth), негативы из
  «Not right?» (flag-render), выходы Kolors/Gemini — **только eval** (ToS).
- Пер-рендер экономика в ledger уже пишется (duration_ms, provider).

### Stage C — селф-хост своей модели (гейт: ≥ ~650 рендеров/день)
- База: SDXL-inpaint + pose-кондиционирование (DWPose/MediaPipe — лицензионно
  чистые), garment-encoder по образцу CatVTON-архитектуры, веса свои.
- Инфраструктура: **serverless GPU** (RunPod serverless / Modal), не dedicated
  A100 — при нашем трафике dedicated жжёт ~$1.4k/мес простоя.
- Breakeven против fal: $0.07/рендер vs A100 $1.9/ч → ~27 рендеров/час
  постоянной загрузки. Ниже — fal дешевле, выше — своя.

## Что НЕ делаем и почему
- SMPL-X регрессия (CLIFF/SPIN) → лицензия + не нужна диффузионному стеку.
- UV-проекция одежды на меш → заменена garment-encoder'ом внутри VTON-модели.
- Клиентский TPS-варп → отменён этим же пивотом; клиент = browse-слой
  (пины по кейпоинтам), реализм целиком на бэкенде.

## State-flow контракт двух ярусов (обновлено после пивота «собери лук → сделай на мне»)

```
TIER 1 · АТЕЛЬЕ (мгновенно, $0)
  state: worn = {top?: item, bottom?: item}        // клиент, в памяти
  клик по чипу → cutout-кэш → pin по якорям → <0.1s
  CTA «✦ Make it real» виден при worn ≠ ∅

TIER 2 · КОММИТ (один вызов на весь лук)
  1 вещь  → {garmentId, category}   → Kolors  (~16s, $0.07)  → bucket vton (public)
  2+ вещи → {garmentIds: [...]}     → Gemini  (~20-40s, ~$0.04) один рендер всего лука
            → bucket generations (private) + generations{type:'tryon', succeeded}
            → ЛУК ПОЯВЛЯЕТСЯ В MY LOOKS БЕЗ ПРАВОК КЛИЕНТА
  оба пути → look_generations (экономика: provider, duration_ms)
  квота: burnFree ПОСЛЕ успеха; 402/409/422 до всяких трат

Клиент: batch идёт через 150s-транспорт БЕЗ ретраев (ретрай = второй счёт);
кнопка блокируется на время генерации, window.vtonDone() возвращает её.
```

Почему batch = Gemini, а не «Kolors пакетом»: Kolors принимает ровно одну
вещь за вызов — «пакетный Kolors» это N последовательных вызовов = N×$0.07 и
N×16s. Один Gemini-рендер всего лука дешевле и быстрее; точность отдельных
вещей ниже колорсовской, но коммит-лук — это композиция, и там Gemini с
референсами всех вещей работает (та же механика, что в проде у render-look).
